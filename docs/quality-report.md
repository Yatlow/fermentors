# מערכת דיווחי תקלות — מבשלת שפירא

## שלב ראשון: קליטה ללא שליחת מייל
הדיווח מתבצע בטופס ציבורי, מועבר ל־Firebase Cloud Function לאימות
Turnstile ותקינות קבצים, ומנותב לקריאת HMAC חתומה אל פרויקט Apps Script
הקיים של הפרמנטורים (ללא הרשאות נוספות לחשבון brewcrew).

`server/QUALITY_REPORT_SERVICE.js` כותב לגיליון בקרת האיכות הקיים,
מקצה מספר פנייה ומטפל במניעת כפילויות. המערכת מקבלת עד 4 תמונות/סרטונים (עד 14MB לקובץ, 22MB יחד) ומעבירה אותם ל־Drive ישירות בבקשת HMAC חתומה דרך Apps Script, ללא Firebase Storage. דיווח עם קבצים לא יוצג כהצלחה לפני קבלת אישור שמירה; בעת כשל המשתמש יכול לנסות שוב עם אותם קבצים ומזהה שליחה.
אין כרגע שליחת דוא״ל; MailApp/GmailApp אינם נקראים כלל.
הדיווח נחשב מעובד בהצלחה כאשר גיליון/Drive נשמרו, ללא תלות במייל.

הגיליון הוא מקור הנתונים: `19urjK3mUk1vO1clZ2IFDq-3ORqLeX5edBLmBeDwIud4`.
תיקיית מדיה: `1FrGg-gBKRyCSsw4EHTq8qb6zJEpWaQSn`.
בעמודת סטטוס ההתראה AC נרשם `מייל מושבת`, וכן סימון 3+ אירועים
נפרדים באותה בירה ואצווה כשהרף נחצה.

Firestore שומר מספר פנייה, אירוע, מספר אירועים ו־`notificationStatus: disabled`.
פרטי הלקוח לא נשמרים ברשומת האידמפוטנטיות לאחר העיבוד.
כשיוקם Mail Gateway נפרד בעתיד, הוא יופעל עבור דיווחים חדשים בלבד.
אסור לשלוח אוטומטית דוא״ל בדיעבד עבור רשומות `disabled`, ללא החלטה מפורשת.

אין דוח שבועי, אין מעקב מחזורי קבוע, ואין OAuth של brewcrew בשלב זה.

## לפני פרסום
יש לאמת בחשבון המפרסם של Apps Script גישה ל־Sheets, Drive, Firestore
וללא תלות בבאקט Firebase Storage; לבדוק קריאה חתומה וקריאה רגילה של הפרמנטורים; ולבצע
בדיקת קצה מבוקרת לרישום, קבצים, מספרי פניות, כפילויות ומניעת מיילים.
לא למזג את PR #252 עד שכל בדיקות התרחישים והרשאות הגישה אומתו.
לתיעוד המלא: `docs/quality-current-script.md`.

## סדר עמודות
הסקריפט מבצע בהפעלתו הראשונה מעבר חד-פעמי של העמודות, בלי לדרוס מידע קיים: J סוג התקלה, K תיאור התקלה, L סוג האריזה, M מק״ט. עמודות הטיפול הקיימות מוזזות ימינה, והשדות הטכניים נשארים ב־X:AD.
